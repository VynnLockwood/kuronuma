# Security fixes S3 and S2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the remaining small security findings agreed before going open source: OAuth protocol errors never redirect before the user has signed in (S3), and four hardening items (S2): per-user caps, cleanup of unused registered clients, quoted category names in tool text.

**Note on scope:** the original written list for S2 was lost when the earlier working session was compacted. This plan rebuilds it from a fresh read of the code. Items that could not be confirmed as real gaps are listed under "Not planned" so the owner can add them back before merging this plan.

**Architecture:** No migrations and no new dependencies. S3 is a change to `parseAuthz` and `fail` in Cerberus. Caps are checked in the modules through a new `Count…` method on each store interface (a count before an insert; a tiny race can overshoot a cap by a row, which is fine). Client cleanup is one new store method called from `CleanupExpired`.

**Tech Stack:** Go. Tests use the repo's existing fakes; run through `/home/claude/scratch/gotest.sh` (stdlib packages) plus CI (store and the Postgres-backed packages).

## Findings (verified in the code)

- **S3.** `parseAuthz` marks four errors `redirect: true` (bad `response_type`, missing or non-S256 PKCE, unknown scope, wrong `resource`). `fail` then sends the browser to the client's `redirect_uri` with `error` and `error_description`, **before the user has signed in or approved anything**. Client registration is open, so a redirect URI only means "someone registered it", not "someone trusted it". Anyone can register a client with a URI they control and make our domain bounce a visitor there: an open redirect on our origin that carries our `iss`. After the fix the user sees our own error page instead. The deny button after consent still redirects (that is the user's own decision).
- **S2 caps.** Categories are capped at 100 (`themis.MaxCategories`), but transactions, memory items (tasks, to-dos, notes) and payee rules are not capped per user. One approved assistant, or a bug, can fill the database.
- **S2 clients.** `CleanupExpired` removes expired codes and tokens but never registered clients, so open registration grows `oauth_clients` forever.
- **S2 category names.** Some tool messages already use `%q` (`themis.go`), but the rename, merge and `category_created` paths and the module error texts need an audit: a category name is user-supplied text that an assistant reads as tool output.

## Global Constraints

- Every query on user data filters by the authenticated user's id (unchanged). No user id from arguments.
- Caps: 50,000 transactions, 5,000 memory items, 500 payee rules per user, as named constants next to `themis.MaxCategories`-style docs. Updating or deleting existing rows is never blocked by a cap; hitting one returns a plain tool error telling the assistant to ask the user to delete some (no data in the message beyond the number).
- Client cleanup deletes only clients with no codes and no tokens at all and `created_at` older than 30 days. Cascades are already in the schema. An assistant that still holds the removed client id gets `invalid_client` and must register again, which MCP clients are required to handle.
- Every new or changed error text keeps going through `hermes.Errorf` and quotes user text with `%q`.
- Cerberus changes need owner approval (AGENTS.md): approving this plan gives it for `oauth.go`, `consent.go` and the `store/oauth.go` method named here.

Two branches and two PRs: `fix/oauth-errors-pre-consent` (Task 1) and `fix/limits-and-hygiene` (Tasks 2 to 4). Nothing unfixed is described in detail outside the PR text that fixes it.

## Review Focus

- S3: no path before sign-in and approval can produce a redirect to a client-supplied URI; the error page escapes everything it prints (`html/template`); the deny path still redirects only after a verified, CSRF-checked POST.
- Caps: counted per user (never global); the cap check cannot be skipped by a different argument shape; a rule update or an idempotent re-add is not blocked.
- Cleanup: a client with a live code or token, or one registered less than 30 days ago, is never removed.
- Quoted names: no category name or other user text reaches a tool result unquoted.

## Not planned (could not be confirmed as gaps)

- "Consent scope text": the consent page already lists only the verified request's scopes in plain words (merged in the consent redesign). If the original item meant something else, say so before merging.
