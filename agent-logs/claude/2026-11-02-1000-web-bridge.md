# The web bridge (dashboard PR G)

- Agent: claude
- Date: 2026-11-02
- Branch / PR: feat/web-bridge

## Goal
`POST /api/web/call` runs one registered tool as the signed-in user so the dashboard can use the same handlers as the assistants.

## What I did
- `hermes`: `CallAs` and `AllScopes`; MCP `tools/call` and the bridge share one `run` (timeout, panic recovery, log line). `WebHandler` with the check order method, browser checks, session, body size, JSON, tool.
- New leaf package `internal/core/webguard` for the browser checks (custom header, JSON content type, Origin, Sec-Fetch-Site), reusable by the Connected assistants PR without editing `hermes`.
- `main.go` adapts the sign-in code to the one-method `SessionUser` interface (`cerberus` untouched); `/api/web/call` registered.
- nginx: `location /api/web/`, its own 300/min zone (burst 60) and `client_max_body_size 64k`.
- `docs/design.md`: "Web bridge" section.

## Verified
- Every unit had a failing test first. `gotest.sh` (cerberus, hermes, webguard, themis, atlas, plutus) ok, `gotest.sh vet` ok, `gofmt -l apps/api` empty, `docker compose config -q` with dummy env ok.
- Real spending tools through the bridge: alice and bob isolated both ways, a refused input is a 422 with the tool's text, and the assistants (MCP) see the same records.
- Mutation check by me (hard-code the user: three tests fail) and by the reviewer (14 of 18 mutations caught).

## Not verified / known gaps
- `cmd/kuronuma-api/main.go` and the store cannot be built here (no Go 1.26 toolchain access); CI compiles them. Real Postgres and the real session through the bridge are exercised only by CI and after deploy.
- No Docker daemon: nginx syntax is checked by CI (`nginx -t`) only; I compared the config by reading.

## Decisions and assumptions
- Header is `X-Kuronuma-Web` (the spec said `X-Nemosyne-Web`); `Sec-Fetch-Site: same-site` is refused as well as `cross-site` (stricter than the spec); both approved with the plan.
- Deferred minors: every registered tool's scope goes to web sessions; a missing scope would be an unlogged 500 (cannot happen today); MCP messages are not pinned by tests; two inaccurate sentences in the new docs section (nginx order, who calls `CallAs`); the local dev server would get 403; nginx's own 413/429 are HTML; results carry the assistant-facing `_note`.
- Pre-existing, noted by the reviewer: sessions are not re-checked against `ALLOWED_EMAILS`, and the session cookie has no `__Host-` prefix.
