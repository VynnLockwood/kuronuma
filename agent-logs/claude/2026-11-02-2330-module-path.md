## Verified

It fails on a wrong `go.mod` line, any old path outside history, any import of the new path without a package directory, a stale repository name in the docs, a changed `go.sum`, files outside the expected list, or a changed line that is not an import path. It was seen failing first.
- `gotest.sh` (cerberus, hermes, themis, webguard, atlas, plutus): pass. `go vet`: clean. `gofmt -l apps/api`: no output. Every changed Go file parses.

## Not verified / known gaps
- Compiling `store` and `cmd` against the real third-party modules (pgx, goose, go-oidc) and `go mod tidy` only run in CI.
- The rename is mostly cosmetic for outsiders: the code lives under `internal/`, which Go does not let other modules import. The one real gain: `go install github.com/VynnLockwood/kuronuma/apps/api/cmd/kuronuma-api@latest` now matches the declared path. With no tags it resolves to a pseudo-version; a release would need a tag like `apps/api/v0.1.0`.
