## Deploy and rollback steps (from the review)
- Deploy: `git pull`, then `docker compose -f deploy/docker-compose.yml --env-file .env up -d --build`. This recreates the nginx container, which must happen: its mounted include path changed from `nemosyne-proxy.conf` to `kuronuma-proxy.conf`. If only `api` and `web` are rebuilt, the old nginx container keeps the old mount and will fail to start or reload against the new `nginx.conf` (add `--force-recreate nginx`).
- Check: `docker compose -f deploy/docker-compose.yml exec nginx nginx -t`, and `curl -fsS <your-origin>/api/healthz`.
- What users notice: they sign in again on the web (cookie names changed). Assistant connections keep working (tokens are unchanged); the address does not change in this PR.
- Rollback: redeploy the previous commit with the same command. Sessions created before this deploy come back, because their rows were never removed, including for people who signed out under the new build.
