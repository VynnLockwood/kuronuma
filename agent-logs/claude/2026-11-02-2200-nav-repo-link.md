# Repository link in the top navigation (PR W)

- Agent: claude
- Date: 2026-11-02
- Branch / PR: feat/nav-repo-link

## Goal
Put a link to the public repository in the top navigation of every page, as in the merged plan `docs/superpowers/plans/2026-11-02-skills-readme-nav.md` (PR W).

## What I did
- `lib/brand.ts`: `REPO_URL` defaults to `https://github.com/VynnLockwood/kuronuma`; `NEXT_PUBLIC_REPO_URL` overrides it and an empty value hides the link (header and footer).
- `components/RepoLink.tsx`: an outline button with the GitHub mark, the word "GitHub" from 640 px up, icon only below, accessible name "Kuronuma on GitHub" (Thai: "Kuronuma บน GitHub"), `target=_blank`, `rel=noopener noreferrer`.
- `SiteHeader` renders it for every page (landing en/th, connect, dashboard in every state, 404 en/th) with a new `lead` slot so the app nav comes first, then the button, then the language switch, sign-in or avatar. Mobile header gaps tightened so the signed-in dashboard still fits at 360 px.
- A `github` glyph in `components/icons.tsx` (Octicons "mark-github", MIT).

## Verified
- `nav-repo-check.py` (scratch): PASS on a normal build (link on every page and state at 1280, 1024, 768, 390 and 360 px in English and Thai; href, target, rel, accessible name, label visibility, tap size at least 36 px, no overlap, no overflow, header height, order after the nav and before the controls, focus ring, footer link kept). `nav-repo-check.py empty` on a build with `NEXT_PUBLIC_REPO_URL=`: PASS, and the served page has no repository URL.
- `tsc --noEmit`, `check:design`, `next build` and every earlier browser check (11 of 11): PASS through `v1-gates.sh`.
- Fresh Opus review: no Critical; one Important (button before the app nav; my ordering check could not fail), fixed test-first.

## Not verified / known gaps
- The signed-in dashboard overflows below 360 px (it already did at 320 px before this PR; now by more). Deferred.
- Docker builds do not pass `NEXT_PUBLIC_REPO_URL`, so Docker images use the default; the README sentence about the variable is updated after PR R (#47) merges.
- I did not test the dashboard loading state in the browser check (the reviewer did by hand).

## Decisions and assumptions
- 36 px tap target below 640 px (plan said 40) so the signed-in header fits at 360 px.
- Language comes from SiteHeader's existing `home` prop.
