# Repository and deployment hygiene (S1)

- Agent: claude
- Date: 2026-10-31
- Branch / PR: chore/repo-hygiene (PR link on GitHub)

## Goal
Before the repository goes public the owner asked for a security check. This is the first of three small fix PRs: policy files and deployment defaults. The owner approved the design in chat, including the parts that need approval under AGENTS.md (`deploy/`, `.env.example`, CI, Dependabot).

## What I did
- `SECURITY.md`: private reporting through GitHub's "Report a vulnerability" button, scope, safe testing, supported versions, a pointer for self-hosters. No contact address and no legal safe-harbour sentence (left for the owner to decide).
- `.github/CODEOWNERS`: everything owned by the maintainer.
- `.env.example`: `POSTGRES_PASSWORD` is blank (compose already refuses an empty value, so a placeholder can no longer be used by accident).
- nginx image `1.27-alpine` to `1.30-alpine` in `deploy/docker-compose.yml` and the CI syntax test (1.30 is the current stable line; 1.27 no longer gets security fixes).
- Dependabot watches `/deploy` (compose) so image updates arrive as PRs.
- nginx: rate limits for `/api/auth/me` (new zone, 120 requests a minute per IP, burst 60) and `/.well-known/` (reuses the OAuth zone).
- README: a Security section (report privately, restrict sign-in with `ALLOWED_EMAILS`, strong secrets, TLS, running behind a CDN needs `real_ip`).

## Verified
- Before: `docker compose --env-file .env.example config -q` (with a session secret set) accepted the shipped placeholder password. After: it fails with "required variable POSTGRES_PASSWORD is missing a value", and validates once a password is set.
- YAML parses for `dependabot.yml`, `ci.yml` and the compose file; every `limit_req` uses a declared zone; the exact-match `/api/auth/me` location comes before `/api/`.
- Links: `SECURITY.md`, `README.md` and `LICENSE` exist.

## Not verified / known gaps
- `nginx -t` and pulling `nginx:1.30-alpine` were not run: there is no Docker daemon or nginx binary here. CI runs both; if the tag does not exist CI will fail and I will fix it.
- Nothing deployed. After merging, the owner must turn on private vulnerability reporting (Settings, Code security), or the SECURITY.md instructions point to a button that does not exist.

## Decisions and assumptions
- Chose the minor-pinned stable tag `1.30-alpine` over `stable-alpine` so builds are reproducible and Dependabot can propose bumps.
- The CI change is only the image tag in the nginx test, so the test matches what is deployed.
